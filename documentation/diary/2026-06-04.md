- [onboard-school] (Alek) Fix bug `save_pending_school`: l'agente passava `selection.kind:"product"` (inesistente) → `invalid_union_discriminator`, salvataggio portale KO. Causa: `save_pending_school` esponeva all'LLM lo schema canonico con `selection` discriminato, mentre `add_bundle_to_portal` usa componenti piatti. Soluzione DRY: nuovo `pendingSchoolInputSchema` (componenti piatti `{productSlug, variantSku}`) + helper `toCanonicalPendingSchool()` che normalizza a `selection:{kind:"variant"}` server-side, coerente con add_bundle. L'LLM non emette più il discriminatore. Tool description corretta ("Payload" non ".md su filesystem"). Typecheck verde, normalizzazione validata contro schema canonico.
